# H9: Production data for agent debugging (Round 29)

Date: 2026-10-06. Search budget: 22 of 25 used. Every URL below appeared in a WebSearch result. None was opened directly, because WebFetch is blocked. Claims marked (snippet) rest only on the search-result text. Nothing here comes from customer conversations.

**Verdict: KILL as A. Marginal B at best (5.8, about 10% odds), and I would not spend a founder sprint on it ahead of the round-20 B finalist.**

The three obvious infrastructure layers were all shipped or funded by October 2026:
- **Scoped, auto-expiring, masked access for agents:** hoop.dev, Formal, Dymium, Bytebase, Immuta and Cyera.
- **Privacy-preserving production replicas:** Xata (which bought Privacy Dynamics), Neon anonymized branches, Tonic Structural Agent, Tiger Data Ghost, mirrord and Arga Labs.
- **Production context fed straight into coding agents through MCP:** Speedscale, Multiplayer, Sentry Seer and Tonic Textual MCP.

**The one layer still open:** a "repro compiler". It turns a production failure into a path-equivalent synthetic reproducer (a failing test plus fixtures containing no real customer values), produced inside the customer perimeter, so the agent never needs production data at all. The research behind it dates from 2008 (Castro/Costa/Martin, "Better bug reporting with better privacy"; the REAP line of work). It never shipped as a product because symbolic execution did not scale to web apps. LLM-guided symbolic execution (AutoBug, DrillAgent, LLM-Sym, 2025-26) gives it a real why-now. It still fails on urgency, ROI clarity and competition position, because a masked branch is "good enough" for most bugs.

## 1. Role 1: First-principles product thinker

### Extreme state (2028–2029)
A 300-engineer B2B SaaS company runs 1–3k agent tasks a day, and 20–40% of them want production-shaped data:
- reproducing a ticket;
- validating a migration;
- regression-testing against real distributions;
- building eval sets from customer interactions;
- fine-tuning per-customer models.

Humans asked for production data a few times a week. Agents ask hundreds of times a day, and for **specific records** ("the account that crashed at 03:12"), not generic test data.

### 2nd-order consequences
1. **Masked copies lose the bug.** Generic masking (format-preserving and k-anonymized) breaks the very property that triggers data-dependent bugs: Unicode edge cases, a skewed distribution, the one tenant with 4M rows, a null in a "never null" column. Research shows anonymization harms field-failure reproducibility (Android study, [arxiv 2402.07460](https://arxiv.org/pdf/2402.07460); DP-synthesis DBMS-bug thesis, [AAU](https://projekter.aau.dk/applying-differential-privacy-to-dbms-bug-reporting-a-reproducibility-retention-study-with-synthetic-7556dec1.html)). Agents fail on the masked copy, and engineers escalate to real access.
2. **Access requests become exception requests.** The security team stops approving "access to prod" and starts approving "access to customer X's record for ticket Y". That volume is O(bugs × agents), which no human team can approve, so approval becomes rubber-stamped or automated.
3. **Agent context becomes a new leakage surface.** Data copied into prompts, transcripts, eval sets and fine-tuning corpora outlives the ticket. Deletion requests (DSARs) now have to reach agent transcripts and derived eval sets.

### 3rd-order consequences
4. **The goal flips from "give agents safe data" to "make agents not need data".** The record is evidence. What the agent needs is a **witness**: any input that drives the same code path to the same failure.
5. **Data-derived artifacts (fixtures, evals, fine-tune sets) need provenance and revocation**, because each one is a copy of customer data that compliance has to account for.
6. **Customer contracts start limiting agent use of customer data** (enterprise DPAs with "no AI processing of our records"). A vendor that can debug without touching the data gets a sales advantage.

### Candidate infrastructure layers
| # | Layer | Initial view |
|---|---|---|
| L1 | **Per-task data lease broker:** scoped, auto-expiring, masked views for each agent task | Crowded: hoop.dev, Formal, Dymium, Bytebase, Immuta, Cyera, Gravitee purpose-limitation. **Dead.** |
| L2 | **Repro compiler:** turns a failure into a path-equivalent synthetic witness (failing test plus synthetic fixtures), produced in-perimeter, with a leakage check before anything leaves | **Strongest.** The research exists; no productized vendor found. |
| L3 | **Derived-data ledger:** provenance, TTL and DSAR propagation for every agent-made copy (fixtures, eval sets, transcripts, fine-tune corpora) | Interesting third-order idea, but it is a "record keeper" (round-28 lesson). Relyance, Transcend and Ethyca are one feature away. **Dead as standalone.** |
| L4 | DP eval/fine-tune data foundry | Braintrust trace-to-eval, Tonic Textual, Gretel→NVIDIA, Google JAX Privacy/VaultGemma, OSS trace2train. **Dead.** |

## 2. Role 2: Technical infrastructure architect

**Where it breaks at 100x**
- *Masked replicas* (Xata, Neon, Tonic) scale well in volume, but their fidelity is fixed at masking time. Policy decides what is preserved, not the bug. Fidelity misses are invisible until an agent fails to reproduce the bug.
- *Proxies and gateways* (hoop.dev, Formal, Dymium) mediate access to **live** data. At 100x the decision rule itself becomes the bottleneck ("is this record needed for this task?"). An LLM approver is probabilistic, and every allowed read is a copy into agent context.
- *Traffic replay* (Speedscale) and *session capture* (Multiplayer, Sentry) capture requests, not the database state that made them fail. Their redaction is also policy-driven.
- *mirrord / staging with real data* moves the problem around: staging holds real data, so the perimeter just got bigger.

**The missing primitive.** It is not "safer access". It is a **reproduction artifact with a privacy proof**:
1. **Capture.** At failure time, take a minimal causal slice (the failing request, the rows and keys it touched, the code version, flags), sealed inside the perimeter. Retention is short, and the slice is encrypted to the in-perimeter runner only.
2. **Synthesize.** An LLM-guided path search (concolic/symbolic execution plus a coverage oracle) generates synthetic values that satisfy the same branch constraints and reach the same failure signature. This is REAP / "Better bug reporting with better privacy" (Microsoft Research, [MSR](https://www.microsoft.com/en-us/research/publication/better-bug-reporting-with-better-privacy/)) brought to web stacks, newly feasible with LLM symbolic-execution agents ([AutoBug arxiv 2505.13452](https://arxiv.org/html/2505.13452v1), [DrillAgent arxiv 2602.13574](https://arxiv.org/html/2602.13574v1)).
3. **Verify and release.** Release only if (a) the failure reproduces on the synthetic witness, and (b) a leakage check passes: no field equals or near-matches the original, and k-distance or membership tests are clean. The output is a repo-native failing test plus fixtures. Agents work only on that output.
4. **Standard format.** A "repro capsule" containing code SHA, environment, fixtures, expected failure and a privacy attestation. It could be the OTel-like portable unit, and is also consumable as an eval and regression case.

**Why a platform team can't do it in a sprint.** Path-equivalent synthesis across ORMs, multi-table state and async jobs is a research-grade program-analysis problem, the same reason it stayed academic for 15 years. That fact cuts both ways: it is defensible, but also risky (see kill criteria).

**Where it does not work:** bugs that depend on volume or performance (the 4M-row tenant), races, and bugs that depend on third-party state. Perhaps 30–50% of data-dependent bugs are out of scope. Masked branches stay the fallback.

## 3. Role 3: Skeptical VC partner

**Where is the money?** Test data management is roughly a $1–2B category (Delphix/Perforce, Tonic, K2view, Synthesized, Informatica TDM). Debugging is Sentry/Datadog budget. A repro compiler sits between them and has to take budget from one. The buyer with real budget (CISO / Head of Data Platform) cares about **avoiding access**. The user (engineering) cares about **fixing faster**. That split is a classic sales stall.

**Who captures value?**
- Sentry (Seer already does RCA and hands off to coding agents) owns the failure event and the developer attention. It is one acquisition away from "privacy-safe repro".
- Speedscale already sells "PII-safe sandbox" replay plus MCP context "to reproduce defects with production context".
- Tonic owns the security-buyer relationship for masked data and has shipped agents.

If the repro compiler works, these companies are the natural acquirers, which caps the outcome at a good M&A, not $10B.

**What would make me lead the seed:**
- a founder with program-analysis or symbolic-execution credentials (KLEE/S2E/Mayhem lineage);
- proof on 3 real customers that the witness reproduces 60%+ of data-dependent tickets with zero raw-data access;
- a CISO saying "this removes the need for prod-access grants for engineers and agents".

**What stops me:**
1. "Masked branch + Sentry trace" is good enough for 80% of bugs. Nobody counts the remaining 20% as a budget line.
2. No public evidence that security teams are actually the bottleneck for agent debugging. The pain is inferred.
3. Research-grade technical risk with a long pilot cycle (needs in-VPC deployment, language/ORM coverage).
4. Every adjacent vendor has an obvious "synthetic repro" feature path.

## 5. Finalist format: "Repro compiler: debug production without production data"

- **One-line problem:** Agents and engineers need the exact customer record that broke production to reproduce a bug. Every such grant is a security exception, and masked copies often destroy the bug.
- **Why now:** (1) Agent debugging volume turns data access from occasional into continuous (hundreds of requests a day). (2) Copies into agent context and transcripts create new leakage and DSAR surfaces. (3) LLM-guided symbolic execution (2025-26) finally makes path-equivalent synthesis feasible on dynamic-language web stacks, after 15 years stuck in research.
- **Exact buyer:** Head of Data Platform or Security Engineering lead (budget). Co-sponsor: VP Engineering / Developer Productivity (user value).
- **Exact ICP:** B2B SaaS with regulated customer data (fintech, healthtech, HR/payroll), 100–600 engineers, Postgres + Python/TypeScript/Ruby, Sentry or Datadog, coding agents in daily use, a formal "no prod access for engineers" policy, enterprise DPAs restricting AI processing.
- **Current workaround:**
  - masked branches (Xata, Neon, Tonic);
  - break-glass prod access through hoop.dev, Formal or a bastion;
  - hand-sanitized logs pasted into Claude Code (noirdoc);
  - Speedscale replay;
  - asking the on-call engineer who has access.
- **Why incumbents cannot easily own it:** Masking vendors preserve fields by policy, not paths. Path synthesis is a program-analysis competency they lack. Sentry/Speedscale own events and traffic but not database state. Building the synthesis engine is research-grade. *Weakness: none of them has to own it. "Good enough" is enough for them.*
- **30-day MVP:** In-VPC runner for Postgres + one ORM (Prisma or SQLAlchemy). On a Sentry issue: capture the touched rows, have an LLM-guided search synthesize replacement values that keep the same branch trace (coverage diff = 0 on the failing path) and the same exception, run a leakage check, and emit a failing pytest/jest test plus fixtures as a PR that a coding agent can pick up.
- **Pilot design:** 2 design partners, 50 historical data-dependent tickets each. Pass if: ≥60% reproduce from the synthetic witness; 0 raw values leak (verified by membership and exact-match scans); median time-to-repro under 15 min; the security lead agrees to remove prod-access grants for the covered services.
- **Pricing hypothesis:** $40–120K/yr platform fee per environment plus usage per repro capsule. Anchored against prod-access tooling and Tonic contracts.
- **Expansion path:**
  - repro capsules become regression tests;
  - capsules become eval and fine-tune cases with privacy attestations;
  - a derived-data ledger (TTL/DSAR for agent-made copies);
  - a "data-free support": vendors debug customer-reported bugs without the customer sending data (cross-company, the B2B DPA wedge).
- **Moat:** a corpus of failure-to-witness mappings across stacks; per-ORM/per-framework synthesis adapters; in-perimeter deployment trust. Moderate only.
- **Why $10B+ (the honest case):** If debugging, testing, evals and fine-tuning all route through "witness, not record", the capsule becomes the unit of production evidence for every agent. That is a privacy primitive at the level of tokenization (cf. Skyflow/VGS). **I do not believe this path on the evidence.** The more likely outcome is a $100–500M acquisition by Sentry, Datadog, Tonic or Perforce.
- **Direct competitors and adjacent threats:** Speedscale, Sentry Seer, Multiplayer, Tonic, Xata, Neon, mirrord, hoop.dev, Formal, Dymium, Bytebase, Arga Labs, Tiger Ghost, Air, Braintrust.
- **One sentence to a CTO:** "Your agents can reproduce every production bug as a failing test without anyone, human or agent, ever reading the customer's record, so you can revoke prod access instead of approving it."
- **Hard kill criteria:**
  1. Fewer than 50% of historical data-dependent tickets reproduce from synthetic witnesses at 2 partners.
  2. Security leads won't trade prod-access grants for it (it doesn't replace budget).
  3. Engineering says the masked branch reproduces more than 80% anyway.
  4. Sentry, Speedscale or Tonic ships "synthetic repro from production record" within 6 months.
  5. Each new ORM/framework takes more than 4 engineer-weeks to support.
